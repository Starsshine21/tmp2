## 4. 最终 Actor 目标函数

最终 actor 为 PI0.5 原生 JAX 参数的全量微调，optimizer 为 Adafactor。

### 4.1 Flash PPO

对旧策略生成的随机 flow transition

$$
(x_t, x_{t-\Delta t}) \sim \pi_{\theta_{\mathrm{old}}},
$$

计算 transition ratio：

$$
r(\theta)
=
\frac{
\pi_\theta(x_{t-\Delta t}\mid s,x_t,t)
}{
\pi_{\theta_{\mathrm{old}}}(x_{t-\Delta t}\mid s,x_t,t)
}.
$$

Flash PPO loss 为：

$$
\mathcal L_{\mathrm{PPO}}
=
-\mathbb E\left[
\min\left(
r(\theta)A,
\operatorname{clip}(r(\theta),1-\epsilon,1+\epsilon)A
\right)w_t
\right],
$$

其中：

- $A$ 来自三个 critic 的 two-sided sign-consensus conservative advantage；
- $w_t$ 是 temporal rectification 权重；
- U-state 仍用于计算 state weight；
- `adapt_ppo_clip=false`，U-state 不改变 PPO clip；
- 不做 group std normalization。

### 4.2 固定 Reference KL

当前策略和固定初始 PI0.5 reference 的 transition KL：

$$
\mathcal L_{\mathrm{KL}}
=
\beta\,
\mathbb E_s\left[
D_{\mathrm{KL}}
\left(
\pi_\theta(\cdot\mid s,x_t,t)
\Vert
\pi_{\mathrm{ref}}(\cdot\mid s,x_t,t)
\right)
\right].
$$

当前配置：

```yaml
regularization:
  beta_kl: 0.01

uncertainty:
  adapt_kl_beta: false
```

因此 U-state 不改变 $\beta$。

### 4.3 Success-buffer BC

只对 59 条真实成功 episode 做 flow-matching BC：

$$
x_t=t\epsilon+(1-t)a,\qquad
v^\star=\epsilon-a,
$$

$$
\mathcal L_{\mathrm{succ}}
=
\mathbb E_{(s,a)\sim\mathcal D_{\mathrm{succ}},t,\epsilon}
\left[
\left\|
v_\theta(s,x_t,t)-v^\star
\right\|_2^2
\right].
$$

最终总目标：

$$
\boxed{
\mathcal L_{\mathrm{actor}}
=
\mathcal L_{\mathrm{PPO}}
+0.01\mathcal L_{\mathrm{KL}}
+0.1\mathcal L_{\mathrm{succ}}
}
$$

普通全 replay FM anchor 已关闭：

```yaml
regularization:
  lambda_fm: 0.0
  lambda_success: 0.1
```

原因是全 replay 包含 41 条失败 episode。继续对它们做 BC 会锚定失败行为；OGPO+ 的核心稳定器是 success-buffer BC。

## 5. 精确的低显存梯度实现

单次把 PPO、KL、普通 FM 和 success FM 放进一个 `value_and_grad`，在 A100 40GB 上无法跨步运行。

最终实现把梯度分项计算并搬到 CPU 累积：

$$
g_{\mathrm{policy}}
=
\nabla_\theta
\left(
\mathcal L_{\mathrm{PPO}}
+0.01\mathcal L_{\mathrm{KL}}
\right),
$$

$$
g_{\mathrm{succ}}
=
\nabla_\theta \mathcal L_{\mathrm{succ}},
$$

$$
g
=
g_{\mathrm{policy}}+0.1g_{\mathrm{succ}}.
$$

最后只执行一次：

$$
\theta\leftarrow\operatorname{Adafactor}(\theta,g).
$$

这不是两次 optimizer step，也没有改变总目标的梯度；只是把两个反向图串行执行，降低峰值显存。

## 6. 本轮修复

### 6.1 Actor-only critic 内存

当 `critic.steps_per_actor_step=0` 时：

- 不恢复 critic AdamW optimizer state；
- target critic 和 target DIVL 移到 CPU；
- GPU 只保留 actor 评分所需的 online critic。

### 6.2 PI0.5 optimizer 与同步

- 使用 Adafactor，避免 AdamW 两套全参数二阶矩；
- learning rate 从 `5e-5` 降到 `5e-6`；
- old policy 每步 hard sync；
- `old_policy_ema=0.0`，避免 EMA 物化第三份 PI0.5 参数。

### 6.3 XLA 跨步内存

- frozen rollout 使用 `nnx.jit`，actor state 是动态输入；
- 每步执行 `jax.effects_barrier()`；
- 每步执行 `jax.clear_caches()`，释放持有上一版 immutable actor buffer 的 executable；
- JAX 显存比例为 0.90；
- Slurm 主机内存为 120G。

cache clear 会增加每步编译时间，但避免约 7GB/step 的设备内存增长。

### 6.4 PPO 与 KL 数值一致性

PI0.5 使用 bf16。若 old/current/reference 分别在不同 XLA trace 中计算，660 维 action chunk 上的微小误差会累积，产生错误 ratio 或非零初始 KL。

最终实现保证：

- old 和 current transition log-prob 在同一个 `value_and_grad` trace 中计算；
- current 和 reference transition statistics 在同一个 trace 中计算；
- step 0 时 `importance_ratio_mean=1`；
- step 0 时 `reference_kl=0`。

### 6.5 Compact JAX checkpoint

正式配置每步 hard-sync old policy，所以 checkpoint 边界上：

$$
\theta_{\mathrm{old}}=\theta.
$$

sidecar 不再重复保存完全相同的 old PI0.5 参数。恢复时从 current actor state 重建 old policy，同时正常恢复 Adafactor state。

## 11. 2026-07-29 多候选与 KL 原子回滚

为修复旧正式任务暴露的问题，commit `9c538e2` 实现了：

1. 每个 replay state 独立采样 4 个 flow 候选；
2. 三组 Q-V head 继续执行 two-sided sign consensus，不删除该机制；
3. PI0.5 全量反向按候选做 `gradient_microbatch_size=1`，四份梯度在
   host 上按样本数加权累积；
4. actor learning rate 从 `5e-6` 降到 `1e-6`；
5. success BC 权重从 `0.1` 降到 `0.02`，并对其加权梯度单独设置
   `success_weighted_grad_max_norm=0.2`；
6. 每次提出更新后，在同一批 old-policy transitions 上重新计算
   current-reference KL；
7. 若 post-update KL 非有限或超过 `0.5`，同时恢复 actor 参数与
   Adafactor state，该次更新被拒绝，但训练循环继续。

配置：

```yaml
actor:
  candidate_group_size: 4
  gradient_microbatch_size: 1
  learning_rate: 0.000001
  reject_update_on_kl: true
  max_policy_reference_kl: 0.5

regularization:
  lambda_success: 0.02
  success_weighted_grad_max_norm: 0.2
```
